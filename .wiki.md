# Project Summary
IndexBoard helps AI researchers, students, and teams create and share leaderboards for evaluating models, tools, and methods. Authors can enter scores and uncertainty intervals, describe their methodology, and publish read-only boards while retaining a private edit key. Boards can be created in the editor, from templates, or from a written description using AI.

For AI model comparisons, IndexBoard can retrieve and refresh model data from Artificial Analysis or OpenRouter, with source attribution. Other AI-generated boards retain the draft workflow, with placeholder values flagged for review. Boards are stored in Atoms Cloud. The app supports charts, printing, JSON exports, English and Chinese, and light and dark themes.

The interface now follows the Repro Suite visual style, with a responsive sidebar for IndexBoard sections and links to other Repro Suite apps.

# Project Module Description
- **Board authoring:** Create and edit board details, methodology, metrics, and results. Enter data in a table, paste JSON or CSV, use a template, or generate a draft from a description.
- **AI creation:** For model comparisons, AI identifies requested models and metrics before fetching available real data. Unsupported metrics are omitted with a note. Other descriptions use the draft workflow with placeholder warnings.
- **Live model data:** A backend endpoint accepts model names or a “top N” request. Artificial Analysis is preferred when `AA_API_KEY` is configured; OpenRouter is used otherwise and as a fallback. Model lists are cached for six hours, with stale-cache fallback when a source is unavailable.
- **Model matching and rankings:** Loose model-name matching selects current flagship models and excludes small, batch, and alias variants. Without Artificial Analysis, “top N” returns newest flagship models, not models ranked by evaluation scores.
- **Board viewing and refresh:** Live-data boards show source attribution and fetch time. Owners can save refreshed data; other visitors see updates only in their own view.
- **Discovery:** The home page features a pinned board and lists recent published boards.
- **Analysis and sharing:** View charts, interval whiskers, score-versus-cost comparisons, rankings, and methodology. Public links are read-only; editing requires the private key.
- **Export and display:** Print boards, copy or download charts, and download or re-import board JSON.
- **Navigation and appearance:** A responsive sidebar links to IndexBoard sections and Repro Suite apps. A theme toggle remembers the selected theme in `localStorage` under `repro.theme2`. The language switch supports English and Chinese.
- **Supporting services:** Backend modules provide authentication, database access, storage, settings, health checks, and AI integrations.

# Technology Stack
- **Frontend:** React, TypeScript, Vite, and Tailwind CSS.
- **Backend:** Python, FastAPI, SQLAlchemy, and Alembic.
- **Charts:** Inline SVG charts implemented in the frontend.
- **Cloud and data:** Atoms Cloud database and supporting SDK/API integrations.
- **AI and model data:** LLM gateway for AI board creation; server-side integrations with Artificial Analysis and OpenRouter for model data.
- **Design and localization:** Inter, Noto Sans SC, and JetBrains Mono; English and Chinese translations; persisted light and dark themes.
- **Quality:** ESLint, Playwright configuration, and plugin tests.

# Usage
- Install backend dependencies from `app/backend` with `pip install -r requirements.txt`.
- Install frontend dependencies from `app/frontend` with `npm install`.
- Run frontend linting from `app/frontend` with `npm run lint`.
- Start the frontend development server from `app/frontend` with `npm run dev`.
- Create a frontend production build with `npm run build`.
- Run the backend using `app/start_app_v2.sh`, or start it from `app/backend` with the configured ASGI server.
- Apply database migrations from `app/backend` with `alembic upgrade head`.
- Configure the required Atoms Cloud and database settings before running the application. Set the server-side `AA_API_KEY` to enable Artificial Analysis; otherwise, model data uses OpenRouter, and Artificial Analysis also falls back to OpenRouter if its request fails.
